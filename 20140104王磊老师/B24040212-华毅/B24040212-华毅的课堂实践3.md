## 九、拓展：配置从 Windows 直接访问数据库

讲义最后提到"如果希望通过 windows 直接访问数据库，需要配置 mysql 配置文件和防火墙，自行研究"。本次完成了该拓展，共三步：

### 1. 修改 MySQL 监听地址

MySQL 默认 `bind-address = 127.0.0.1`，只允许本机连接。修改配置文件：

```bash
sudo cp /etc/mysql/mysql.conf.d/mysqld.cnf /etc/mysql/mysql.conf.d/mysqld.cnf.bak
sudo sed -i -E 's/^#?bind-address[[:space:]]*=.*/bind-address = 0.0.0.0/' /etc/mysql/mysql.conf.d/mysqld.cnf
grep -n "bind-address" /etc/mysql/mysql.conf.d/mysqld.cnf
```

修改前后对比：

```text
修改前：31:bind-address		= 127.0.0.1
       32:mysqlx-bind-address	= 127.0.0.1
修改后：31:bind-address = 0.0.0.0
       32:mysqlx-bind-address	= 127.0.0.1   （X 协议端口 33060 仍只允许本机）
```

### 2. 创建允许远程登录的数据库用户

```sql
CREATE USER 'myuser'@'%' IDENTIFIED BY '111111';
GRANT ALL PRIVILEGES ON mydb.* TO 'myuser'@'%';
FLUSH PRIVILEGES;
```

确认用户表：

```text
user	host
myuser	%
myuser	localhost
```

### 3. 配置防火墙并重启服务

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx HTTP'
sudo ufw allow 3306/tcp
sudo ufw show added
sudo systemctl restart mysql
```

`ufw show added` 输出：

```text
已添加的用户规则(查看正在运行的防火墙的 "ufw 状态")：
ufw allow OpenSSH
ufw allow 'Nginx HTTP'
ufw allow 3306/tcp
```

重启后确认监听情况：

```text
LISTEN 0  151      0.0.0.0:3306    0.0.0.0:*
LISTEN 0   70    127.0.0.1:33060   0.0.0.0:*
```

说明：本机 ufw 防火墙处于"不活动"状态，因此规则仅作登记（不影响访问，也为将来启用防火墙做好放行准备）。

## 十二、遇到的问题与解决

| 问题现象 | 原因分析 | 解决方法 |
| --- | --- | --- |
| `apt update` 提示 `cn.archive.ubuntu.com` 的 Release 文件已过期（约 16 小时） | 该镜像站元数据尚未同步更新 | 不影响本次安装（安装源可用），`mysql-server` 正常安装成功；也可更换为清华等镜像源 |
| Windows 无法连接虚拟机 3306 端口 | MySQL 默认 `bind-address = 127.0.0.1`，只监听本机回环地址 | 修改为 `0.0.0.0` 并 `systemctl restart mysql`，同时创建 `myuser`@`%` 用户 |
| 防火墙是否需要放行 | 本机 ufw 处于"不活动"状态，端口本身未被拦截 | 仍登记 `OpenSSH`、`Nginx HTTP`、`3306/tcp` 规则，便于后续启用防火墙时不被锁在门外 |
| 虚拟机系统时间与宿主机不一致（系统内显示为 10-10 17:43） | 虚拟机配置中关闭了 VMware 时间同步（`tools.syncTime = FALSE`），且未启用 NTP | 可在虚拟机中执行 `sudo timedatectl set-ntp true` 开启自动校时 |
| MySQL 8.4 默认认证插件为 `caching_sha2_password` | 8.4 起 `mysql_native_password` 默认禁用 | 使用支持该插件的客户端（MySQL 官方客户端、DBeaver、mysql2 均可正常连接），无需降级认证方式 |
